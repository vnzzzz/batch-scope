# API仕様

この文書は、APIの意味と利用者へ保証する動作の正本です。
パス、パラメーター、ヘッダー、JSON項目の型と必須条件は、GoとHumaの実装から生成する[OpenAPI](../api/openapi.yaml)を正本とします。

## 基本方針

状態確認と検索は、サーバーの状態を変更しない`GET`で提供します。
スナップショット取込は、新しい取込処理を作成して検索先を更新するため、`POST`で提供します。

APIが同期して返すエラーは、RFC 9457のProblem Details形式です。
ジョブIDとジョブネットIDにはパス区切り文字が含まれる場合があるため、検索対象のIDはクエリパラメーターで受け取ります。

検索は、開始時に使用していたスナップショットの**世代**を処理終了まで使用します。
世代の切替と旧世代の寿命は、[SQLiteの世代切替](storage.md#sqliteの世代切替)で定めます。

## API一覧

| Method | Path | 用途 |
|---|---|---|
| `GET` | `/healthz` | プロセスの生存確認 |
| `GET` | `/readyz` | 検索できるスナップショットがあるか確認 |
| `GET` | `/v1/status` | サービス状態の取得 |
| `POST` | `/v1/snapshot-imports` | スナップショットの送信 |
| `GET` | `/v1/snapshot-imports/{importId}` | 取込状況の取得 |
| `GET` | `/v1/snapshots/current` | 現在使用中のスナップショット情報の取得 |
| `GET` | `/v1/targets` | ジョブまたはジョブネットの完全一致検索 |
| `GET` | `/v1/downstream-limit-analysis` | 後続リミットと依存経路の取得 |

Humaが生成したAPIドキュメントを`/docs`、OpenAPIを`/openapi.json`と`/openapi.yaml`で公開します。
取込データ用のJSON SchemaはHTTP APIから配信しません。

`GET /v1/status`の`snapshot`は、検索に使用中の世代を返します。
未取込時は`null`であり、更新取込中は切替前の世代を維持します。
サービス状態と運用者の判断は、[サービスの状態](../operations.md#サービスの状態)を参照してください。

## 対象の検索

`GET /v1/targets`は、`query`をID、名前、完全パスと照合します。
`type`を指定した場合は、`job`または`job_network`へ絞ります。

`query`の指定は必須です。
明示的に指定された空文字と空白だけの値も検索値として扱います。

IDは入力どおり比較します。
名前はUnicode NFKC、前後空白の除去、Unicodeケースフォールディングを適用して比較します。
パスはUnicode NFKCと前後空白の除去を適用し、大文字と小文字を区別して比較します。
前方一致、部分一致、曖昧検索は行いません。

同じノードが複数の検索対象で一致しても一件だけ返し、`matchedBy`で一致した対象を示します。
`ancestorPath`は、対象の所属を最上位から直接の親までの順に示します。

結果は、最初に一致した対象をID、名前、パスの順で比較し、次に完全パス、最後にIDをバイト順で比較して並べます。
完全パスがないノードは、完全パスがあるノードより後に並べます。
同じ入力と検索条件には同じ順序の結果を返します。

一回の検索では最大1,000件を返します。
1,001件目の存在を確認した場合は先頭1,000件を返し、`truncated=true`で全件結果ではないことを示します。

## 後続リミットの取得

`GET /v1/downstream-limit-analysis`は、`targetId`で指定したジョブまたはジョブネットから後続リミットと依存経路を解析します。
`includeEvidence`は、経路を構成するrelationの根拠情報を含めるかを指定します。

受入済みスナップショットでは、該当するリミットを全件返します。
検索を完了できない場合は、不完全な結果を部分成功として返しません。
リミットの抽出範囲、閲覧順、循環、代表経路の意味は[後続リミットの検索](dependency-analysis.md)で定めます。

### レスポンスの構成

`bootId`と`snapshotId`は、サービス起動と解析に使用した世代を識別します。
`target`は検索対象を示します。

リミットは、対象自身の`target`、指定したジョブネット配下の`contained`、依存関係をたどった`downstream`に分けます。
各区分では、`finish_by`をタイムゾーン別に、`max_elapsed`と`raw`を種類別に返します。
種類が異なるリミットを一つの優先順位へ換算しません。

各リミットの`limitOwner`は実際の設定先ジョブ、`scopeRoot`は後続として到達したジョブネット、`treeNodeId`は経路上の設定先を示します。
`max_elapsed`の`duration`は、取込時に固定秒数へ変換できた値を一意なISO 8601 Durationで返します。

`tree`は、返却したリミットとリミット未通過経路を説明する接続を共有して表します。
`uncoveredRoutes`は、リミット設定先を通らずに終端、循環、探索対象外の種別へ達した経路を示します。
`cycles`は、到達可能な探索グラフで検出した強連結成分と、その成分を説明する一周分の経路を示します。

`includeEvidence=false`でも、relationの種類、生成元、確実性は返します。
`includeEvidence=true`の場合だけ、表示経路に採用したrelationへ`evidence`を追加します。
リミットの`fact`には、`includeEvidence`の値にかかわらず`evidence`を追加しません。

成功時は、受入済みスナップショットに対する全件解析だけを返します。
部分成功や未解析範囲を表す項目は返しません。
キャンセル、時間上限、データベースエラー、内部不整合で解析を完了できない場合は、成功レスポンスではなくProblem Detailsを返します。

## スナップショットの取込

`POST /v1/snapshot-imports`は、`application/vnd.batchscope.snapshot+gzip`のアーカイブをリクエストボディで受け取ります。
リクエストボディの保存までは同期して行い、展開、検査、SQLite作成、検索先の切替は非同期で行います。

受信が完了して取込を開始した場合は、本文のない`202 Accepted`を返します。
`Location`は取込状況を確認するURI、`Retry-After`は次の確認まで待つ秒数です。

### 取込状況

`Location`のURIへ`GET`を送り、取込リソースの状態を確認します。

| 状態 | 意味 |
|---|---|
| `accepted` | リクエストボディの保存が完了した |
| `validating` | アーカイブとスナップショットの制約を検査している |
| `building` | 検査済みデータからSQLiteを作成している |
| `activating` | SQLiteを検査して検索先を切り替えている |
| `succeeded` | 検索先の切替または同一内容の再利用が完了した |
| `failed` | 取込に失敗した |

`snapshotId`は検査で判明した後に公開します。
失敗時の`error`はProblem Detailsと同じエラー種別を持ち、安全に特定できる場合だけ入力内の位置と理由を追加します。
取込履歴の保持と再起動時の扱いは[取込履歴](../operations.md#取込履歴)を参照してください。

### 現在使用中のスナップショット

`GET /v1/snapshots/current`は、検索に使用中の世代の識別子、生成日時、取込形式の版、件数を返します。
検索可能な世代がない場合は`snapshot-not-loaded`を返します。
内容の同一性を判定する内部値は公開しません。

### 同時取込と再送

同時に実行できる取込は一件です。
進行中の取込がある場合、二件目はリクエストボディを読む前に`snapshot-import-in-progress`を返します。

現在世代と同じ`snapshotId`を再送した場合、展開後の`manifest.json`、`nodes.ndjson`、`relations.ndjson`のbyte内容がすべて同じときだけ同一内容として扱い、SQLiteを再構築せず`succeeded`にします。
JSONとして意味が同じでも、空白、改行、objectのキー順などで展開後ファイルのbyte内容が変われば異なる内容です。
同じ`snapshotId`で内容が異なる場合は、非同期取込を`failed`とし、`snapshot-id-conflict`を記録します。

アーカイブ内のファイル順、権限、更新日時、gzipの圧縮方法は展開後三ファイルのbyte内容ではないため、これらだけが異なる再送は同一内容として扱います。
同一性判定に使用する内部のfingerprint値とhash形式は公開しません。

## 大容量リクエストの制御

圧縮後サイズの500 MiBは受信中に検査し、リクエストボディをメモリへ一括読込しません。
受信は10分で打ち切り、取込枠を遅い送信元が保持し続けることを防ぎます。
時間上限を超えた場合は、受信を中断して取込予約と一時ファイルを破棄します。

後続リミット取得は10秒で打ち切ります。
要求のキャンセルまたは時間上限では蓄積済みの結果を返さず、`analysis-timeout`として終了します。
この時間上限は、正常系の性能目標ではなく、異常時に処理と検索世代の保持を終了させる上限です。

運用時に確保する資源とすべての入力上限は[サービス側の上限](../operations.md#サービス側の上限)を参照してください。

## エラー

| Status | 種別 | 利用者が判断できること |
|---:|---|---|
| 400 | `invalid-request` | クエリパラメーター、要求形式、受信時間が受理条件を満たさない |
| 404 | `target-not-found` | 指定した検索対象が現在世代にない |
| 404 | `import-not-found` | 取込履歴が保持されていない |
| 409 | `snapshot-import-in-progress` | 別の取込が進行中である |
| 409 | `snapshot-id-conflict` | 同じIDのスナップショットと内容が異なる |
| 413 | `snapshot-too-large` | アーカイブまたは展開内容がサイズ上限を超えた |
| 422 | `snapshot-capacity-exceeded` | 完全解析を保証する初期対応規模を超えた |
| 422 | `invalid-snapshot` | スナップショットの形式または意味上の整合性が不正である |
| 503 | `snapshot-not-loaded` | 検索可能なスナップショットがない |
| 503 | `analysis-timeout` | 解析が完了前にキャンセルまたは時間上限へ達した |
| 500 | `internal-error` | サーバー内部で処理を完了できなかった |

受信後の取込が失敗した場合は、取込リソースの`error`で報告します。
`invalid-snapshot`と`snapshot-capacity-exceeded`には、対象ファイル、行番号、JSON Pointer、理由コードを含める場合があります。

Problem Detailsの`type`と取込リソースの`error.type`には、上表の種別に対応する`/problems/<種別>`を設定します。
フレームワークが生成する上表以外のエラーは、`about:blank`を使用します。

## OpenAPIの管理

手書きのOpenAPIは置きません。
Goのルート定義と型から生成した[`docs/api/openapi.yaml`](../api/openapi.yaml)をGit管理し、実装との差分を通常検査で検出します。
生成手順は[開発コマンド](../development/development.md#開発コマンド)を参照してください。
