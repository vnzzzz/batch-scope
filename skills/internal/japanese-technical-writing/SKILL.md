# 日本語技術文書

日本語技術文書の表記と構成の正本は[技術文書の書き方](../../../docs/development/writing-style.md)である。
執筆前に正本を読み、規則の追加または変更は正本で行う。

一文ごとに改行し、一つの段落では一つの論点だけを扱う。
同じ概念には同じ用語を使い、同じ仕様を複数の文書へ重複して記載しない。
詳細な表記、図表、配置、説明範囲、推敲の規則は正本に従う。

## 文書種別ごとの適用

| 文書種別 | 適用する構成 |
|---|---|
| API仕様 | 入出力、条件、例外を直接記載し、引き込む導入、物語的な展開、比喩による説明を導入しない |
| 運用手順 | 実行環境、前提、操作、確認結果を順に記載し、読み物向けの演出を導入しない |
| 開発手順 | 作業条件と再現できる手順を直接記載し、読み物向けの演出を導入しない |
| 技術ブログ | 読者の前提と読む動機を最初に示し、内容に必要な範囲で読み進めやすい展開を採用してよい |
| チュートリアル | 読者の前提と達成する目的を最初に示し、操作の理由が追える展開を採用してよい |
| 設計背景の長文説明 | 読者が知っている状況と設計判断の動機を最初に示し、判断へ至る流れを説明してよい |

## 外部参考資料

外部資料は規則の正本ではなく、執筆方針を検討するための参考資料として扱う。
エージェントは実行時に外部URLを取得せず、このSkillとリポジトリ内の正本だけで判断する。
出典、確認日、採用範囲は[外部参考資料](references/sources.md)を参照する。

## 執筆後の確認

- 一文ごとに改行し、一段落を一論点に限定したか確認する。
- 用語が正本と関連文書で統一されているか確認する。
- 別の文書にある仕様を複製せず、正本へのリンクに置き換えたか確認する。
- 事実、推測、例外、処理上限を正確に区別したか確認する。
- 文書種別に不要な演出、比喩、進行だけを述べる文を削除したか確認する。
- コマンドの実行環境と、リンク先が正しいか確認する。
